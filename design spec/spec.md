# Sample DNA Tagger — Design Spec

> **For agentic workers:** Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task.

**Goal:** A desktop app for music producers that AI-tags their sample library by energy, texture, emotional quality, and instrument type — then lets them find anything with natural language search ("high tension, no transients, mid-high range") or browsing by category, pack, or recency.

**Platform:** Windows + macOS desktop app

## Architecture

### Overview

The app is a single Python process. FastAPI serves both the REST API and the compiled React SPA as static files. On launch, a launcher script starts the server and opens a native window via `pywebview` — so it looks and feels like a desktop app, not a browser tab. PyInstaller bundles the whole thing, including the Python runtime and ML models, into a single distributable for Windows and macOS.

```
┌─────────────────────────────────────────────┐
│                 Desktop App                  │
│  pywebview window → localhost React SPA      │
│                                              │
│  ┌──────────────────────────────────────┐   │
│  │         FastAPI (Python)             │   │
│  │  ┌──────────┐ ┌───────┐ ┌────────┐  │   │
│  │  │ Scanner  │ │  LLM  │ │ SQLite │  │   │
│  │  │  Engine  │ │ Layer │ │   DB   │  │   │
│  │  └──────────┘ └───────┘ └────────┘  │   │
│  └──────────────────────────────────────┘   │
└─────────────────────────────────────────────┘
```

### Three internal layers

**Scanner Engine** — a background thread pool that walks watch folders, runs local audio analysis (librosa + Essentia), then passes structured results to the LLM layer for expressive tagging. Runs incrementally — only processes files that are new or modified since last scan. Writes scan progress to a status table polled by the frontend.

**LLM Layer** — receives structured audio features (never audio files) and sends them to any OpenAI-compatible endpoint. Returns expressive tags: energy, texture, mood, emotional quality, motion, and instrument classification. The endpoint base URL, API key, and model name are all user-configurable.

**SQLite Database** — stores all samples, tags, ratings, scan roots, and settings. Full-text search via SQLite FTS5 over a virtual table indexing filename, AI tags, and user tags together.

### FTS5 virtual table

```sql
CREATE VIRTUAL TABLE samples_fts USING fts5(
  id UNINDEXED,
  filename,
  ai_tags,
  user_tags,
  instrument_category,
  instrument_type,
  instrument_subtype,
  pack_source,
  content='samples',
  content_rowid='rowid'
);
```

Kept in sync via triggers on `samples` INSERT, UPDATE, DELETE.

## Classification Hierarchy

```
instrument_category  →  instrument_type    →  instrument_subtype
       Drums          →      Kick           →    Sub Kick
       Drums          →      Kick           →    Punchy Kick
       Drums          →      Hi-hat         →    Open Hi-hat
       Drums          →      Hi-hat         →    Closed Hi-hat
       Drums          →      Snare          →    Rimshot
       Synth          →      Synth Pad      →    Warm Pad
       Synth          →      Synth Pad      →    Cold Pad
       Synth          →      Synth Lead     →    Distorted Lead
       Bass           →      808            →    Distorted 808
       Bass           →      Sub Bass       →    Round Sub
       Atmosphere     →      Drone          →    Textured Drone
       FX             →      Riser          →    Filtered Riser
```

All four dimensions (category, type, subtype, pack_source) are filterable in both Search and Browse. The LLM is responsible for populating all four during the tagging pass. The user can override any of them per sample.

## Local Audio Analysis

Run per file by the Scanner Engine using `librosa` and `essentia`. Results are stored as raw floats; display labels are computed at query time.

| Feature | Library | Output |
|---|---|---|
| BPM | librosa | Float (e.g. 132.4) |
| Key | librosa | String (e.g. `C#m`) |
| Duration | librosa | Float seconds |
| RMS energy | librosa | Float → `low / medium / high` |
| Spectral centroid | librosa | Float Hz → `sub / low / mid / high / air` |
| Spectral flatness | librosa | Float 0–1 → `tonal / mixed / noisy` |
| Zero crossing rate | librosa | Float → `none / low / medium / high` transients |

Supported formats: WAV, AIFF, MP3, FLAC, OGG.

## LLM Tagging

After local analysis, the Scanner Engine sends a structured prompt to the configured LLM endpoint. **No audio is transmitted** — only the feature values extracted locally.

### Prompt structure

```
You are a music production assistant. Given these audio features, return a JSON object with expressive tags.

Features:
- BPM: 132
- Key: C#m
- Duration: 4.2s
- Energy: high RMS
- Frequency range: mid-high (centroid 3800Hz)
- Texture: tonal (flatness 0.08)
- Transients: none (ZCR 0.02)

Return JSON:
{
  "instrument_category": "Synth",
  "instrument_type": "Synth Pad",
  "instrument_subtype": "Warm Pad",
  "energy": "high",
  "texture": "smooth",
  "frequency_range": "mid-high",
  "transient_density": "none",
  "mood": ["tension", "dark", "cinematic"],
  "motion": "static",
  "ai_tags": ["tension", "dark", "smooth", "mid-high", "cinematic", "sustained"]
}
```

### Provider configuration

Any OpenAI-compatible endpoint is supported. Preset options in Settings auto-fill `llm_base_url`:

| Preset | Base URL |
|---|---|
| Deepseek | `https://api.deepseek.com/v1` |
| Kimi (Moonshot) | `https://api.moonshot.cn/v1` |
| OpenAI | `https://api.openai.com/v1` |
| Ollama (local) | `http://localhost:11434/v1` |
| Custom | User-entered |

Model name is always user-editable regardless of preset.

## API Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/api/samples` | List samples. Accepts `tags`, `category`, `type`, `subtype`, `pack`, `rating`, `unreviewed`, `not_played_days`, `sort`, `limit`, `offset` |
| GET | `/api/samples/{id}` | Single sample detail |
| PATCH | `/api/samples/{id}` | Update rating, user_tags, notes, instrument fields, pack_source |
| GET | `/api/search/parse` | Parse natural language query → structured tag list via LLM |
| GET | `/api/browse/facets` | Return counts for sidebar: categories, types, packs |
| GET | `/api/scan/status` | Current scanner state: idle / scanning, queued count, error count |
| POST | `/api/scan/start` | Trigger full rescan of all roots |
| POST | `/api/scan/roots` | Add a watch folder |
| DELETE | `/api/scan/roots/{id}` | Remove a watch folder |
| GET | `/api/settings` | All settings as key/value |
| PUT | `/api/settings` | Update settings |
| POST | `/api/settings/test` | Test LLM connection |

## UI

### Search mode

Natural language input at the top. On submit, `/api/search/parse` sends the query to the LLM which returns a structured tag list. Tag pills appear below the search bar — each pill is removable, and additional pills can be added manually. Results update live as pills change.

Each result row shows: play button, filename, pack · type · subtype breadcrumb, key AI tags, duration, drag handle, copy-path button, star. Clicking a row expands it inline to show a waveform scrubber and the user tag editor. User tags are displayed in green to distinguish them from AI tags.

### Browse mode

Left sidebar with three sections:
- **Quick filters** — Not heard recently (>30 days), Unreviewed (rating = 0, no user tags), Starred — each shows a count
- **By category** — collapses/expands into instrument types on click
- **By pack** — lists all detected packs with counts

Main panel shows a breadcrumb of the current drill-down, a row of mood/energy sub-filter chips drawn from the current result set, and the same result rows as Search. Sort options: last played, date added, filename. "Not heard recently" items show days-since-played in amber.

### Settings

Three sub-pages:
- **Library** — watch folder list (add/remove/rescan), scan status dashboard (indexed / tagged / queued / errors)
- **AI Provider** — preset dropdown, base URL, model name, API key, Test Connection button with inline pass/fail indicator
- **About** — version, acknowledgements

## DAW Integration

Two mechanisms, both available on every sample row:

**Drag to DAW** — native file drag initiated from the drag handle icon. Uses pywebview's `js_api` to trigger an OS-level file drag so the sample can be dropped directly into Logic, Ableton, Bitwig, or any DAW that accepts file drops.

**Copy path** — copies the absolute file path to the clipboard. One click, no dialog.

| Target | Mechanism |
|---|---|
| macOS | PyInstaller → `.app` bundle → zip or DMG |
| Windows | PyInstaller → `.exe` → zip or NSIS installer |

The React SPA is built (`npm run build`) and its `dist/` output is bundled into the PyInstaller spec as data files, served by FastAPI on startup. `pywebview` opens `http://localhost:<port>` in a native OS window with no browser chrome.

A `launch.py` entry point: starts FastAPI on a random available port, waits for it to respond, then opens the pywebview window. On window close, the FastAPI process exits.

## Scan Flow

```
Add watch folder
      ↓
Scanner walks folder tree (background thread)
      ↓
For each audio file:
  ├─ Already in DB and mtime unchanged? → skip
  ├─ New or modified?
  │     ↓
  │   Run local analysis (librosa/Essentia)
  │     ↓
  │   Send features to LLM → receive tags
  │     ↓
  │   Write/update samples row
  └─ Error? → log to errors table, continue
      ↓
Update scan_roots.last_scanned_at and file_count
      ↓
Idle
```

Rescan is triggered manually per folder or globally. File-system watching for live updates is out of scope for v1.

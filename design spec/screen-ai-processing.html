Where does the AI analysis run?

This shapes the whole architecture — pick what fits your workflow and privacy needs.

A

Fully Local

Audio analysis runs on your machine using open-source models (Essentia, CLAP, ONNX). No internet required, no API costs, complete privacy — your samples never leave your drive. Slower first-run scan but instant after that. Works offline always.

Pros

  • Privacy — files stay local
  • No ongoing cost
  • Works offline
  • Faster repeated queries

Cons

  • Heavier install (~500MB models)
  • Slower initial scan
  • Less flexible tagging vocabulary
B

Cloud AI (OpenAI / Gemini)

Audio is transcribed or fingerprinted locally, then described via an LLM API for rich semantic tagging. Richer language understanding — "liminal", "glacial", "anxious pulse" — beyond what local models produce. Requires internet and API key.

Pros

  • Richer, more expressive tags
  • Better natural language search
  • Lighter app install

Cons

  • Samples sent to third party
  • API costs at scale
  • Requires internet
C

Hybrid (Recommended)

Local models handle the signal analysis — BPM, key, spectral energy, transient density, frequency range. An LLM then reads those structured numbers and generates expressive semantic tags. Only metadata goes to the cloud, never audio. Best of both.

Pros

  • Audio stays local
  • Rich descriptive tags from LLM
  • API cost is tiny (metadata only)
  • Works partially offline

Cons

  • Needs API key for tagging
  • More moving parts

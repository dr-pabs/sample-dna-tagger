Desktop app framework

Windows + macOS target. All three options use a React web UI — the difference is how the backend is packaged.

A

Electron + Python sidecar

Electron renders a React UI (same stack as inKubator). Python runs as a bundled sidecar process handling audio analysis (librosa/Essentia) and LLM calls. Proven pattern used by many audio tools.

Pros

  • Familiar React/Next.js stack
  • Large ecosystem, great devtools
  • Full OS integration (file dialogs, tray)

Cons

  • Heavy install (~200MB+ with Python)
  • Two runtimes to manage
  • Slower startup
B

Tauri + Python sidecar

Tauri (Rust) renders a React UI in a lightweight native webview. Python runs as a sidecar for audio analysis. Much lighter than Electron — the Rust core handles file system, SQLite, and window management.

Pros

  • Tiny install (~10MB shell + Python)
  • Fast startup, low memory
  • React UI — familiar stack

Cons

  • Rust required for core features
  • Sidecar IPC adds complexity
  • Smaller community than Electron
C

Python FastAPI + React (Recommended)

Python (FastAPI) serves the React SPA locally. The app is one Python process — audio analysis, LLM calls, SQLite, and the UI server all in one. Packaged with PyInstaller. Opens a native webview (or browser tab) on launch. Simplest possible architecture.

Pros

  • One language for all backend logic
  • Python-first audio ML ecosystem
  • No IPC complexity
  • Easy to extend and debug

Cons

  • Large install (Python + deps)
  • Native feel requires extra work
  • PyInstaller bundling can be fiddly
